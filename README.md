# 银翼凌云 1.0

Android 离线 3D 空战游戏，含 12 架机型、研发与 GP 经济、5 对 5 空域争夺和朝鲜战役。正式版 1.0 的普通科技树仅开放中、德、美、苏四系 Rank I—II，共 8 架飞机。

沿用 v18 的加载、存档失败回滚、模型资源释放、地形采样和性能修复，以及用户提供的图标与菜单循环 BGM-1。新增德系 Rank II / BR 2.0 的 Bf-109 C-1：390 耐久，四挺 MG17，合计 1840 发，单管 1200 发/分钟，弹速 855 m/s，伤害 14；极速 465 km/h，最低 124 km/h，爬升 13.2 m/s，水平/垂直转弯 19.0 / 11.3 秒。

## v22 地形与独立研发

空域争夺的 AI 首次发现敌人后随机机动 1–2 秒，再以错开的航线完成第一次交错；继续飞离至少 2 秒并拉开距离，之后恢复原有盘旋、拦截与能量战。首次交错和拉开阶段不开火。后续迎头射击需要距离不超过 325 m、预测瞄准误差不超过 1.2°、估计命中概率达到 0.72；以 0.18 秒短点射和 0.8 秒间隔限制持续对射。地面回避与边界返航保持优先。

新存档和无效操控设置默认使用摇杆，玩家已明确保存的操控方式继续保留。主菜单左上角增加不遮挡头像操作的水印覆盖板。

Bf-109 C-1 的追尾视角与 Bf-109 B-1 一致，包括相机距离、高度和窄屏适配。

朝鲜地图使用用户提供的 mountain_3 至 mountain_6 四个 GLB，测量实际边界后，每块各 3 km × 3 km，按 X/Z 相邻边组成 6 km × 6 km 地图。共边高度与法线一致，X/Z 没有面积重叠；底层平面在海平面下 1.5 m。移除旧版 100 m 压平和固定绿色贴图过渡，四块地形共享一张 4096² 图集，每块有效纹理精度保持 2048²。

场外距离从矩形战斗区边界起算：0–6 km 复用场内模型、几何和纹理；6–12 km 使用低面数模型；12 km 之外逐渐进入地形雾，16 km 外完全融入背景，并有底层地面兜底。地形雾使用世界坐标计算，不会因为相机到接缝的距离而在场内形成雾带。近景场外的高度采样与可见模型一致，战斗边界仍是 6 km × 6 km。

各国家科技树按本系前一个 BR 阶段独立解锁。苏系 I-15 → I-16 → MiG-3；德系 B-1 → C-1；美系不依赖中、德、苏飞机。购买入库 I-16 即可研发 MiG-3，不需要 C-1。已拥有的飞机和研发进度保留。

可使用 Python、NumPy、Pillow 和四个原始 GLB 重建地形：

```sh
python3 scripts/build-korea-terrain.py tile3.glb tile4.glb tile5.glb tile6.glb
```

`data/korea-terrain.json` 记录原模型文件名、SHA-256、拼接尺寸和模型面数。回归检查包含真实地形上的三组 110 秒 5 对 5 模拟，以及共边与法线检测、864 个场外覆盖采样，以及场内强制雾/关闭雾像素对比；浏览器检查验证实际 WebGL 模型、菜单与战斗界面。

## 开发

```sh
npm ci
npm run build:source
npm run check
npx playwright install --with-deps chromium
npm run check:browser
```

可编辑源码位于 `src/`，按飞行、操控、武器、AI、对局、地图、音频、进度和界面划分。`src/parts.json` 明确构建顺序；运行时可变数据归属七个状态对象。子系统目前仍在一个编译作用域中协作，避免在这次修复中同时改变飞行与对局协议。

飞机模型、飞行、武器、AI、研发成本、备弹和音效信息统一在 `data/aircraft.json`。图鉴数字从同一份数据计算，不再手工维护平行表。`game.mjs` 与 Android assets 中的 `index.html` 是确定性构建产物，请通过 `npm run build:source` 更新。

模型 GLB 克隆共享几何、材质与纹理；只有实例创建的螺旋桨模糊面和起落架舱门等资源由实例释放。炸弹拥有自己的几何与材质，离场和重置均释放。

BGM-1 使用 `audio/menu-bgm-1.mp3`，所有菜单与结算页面共用一个循环音频实例。进入对局、暂停、观战与切到后台停止菜单音乐，返回菜单恢复。Android WebView 允许菜单自动播放；普通浏览器可能需要第一次点击。

## Android 构建

使用 JDK 17、Gradle 8.9、Android SDK / Build Tools 35：

```sh
gradle --no-daemon assembleDebug
```

CI 会验证生成文件、运行逻辑回归、地形共边、场外覆盖采样检查和真实 Chromium WebGL/音频/UI 检查，再输出 APK。浏览器检查使用软件渲染，不能代替 Android 真机帧率与听音验收。

应用包名保持 `com.luna.skyduel`，正式版本为 `1.0` / `versionCode 22`。最终交付 APK 使用已恢复的原游戏签名，证书与 v17 一致，可覆盖同签名旧版。1.0 使用独立的新存档格式和存储键，旧版飞机、钱包、研发及操控设置不再读取。CI 的中间 debug APK 使用临时调试签名，最终签名步骤在仓库外执行；签名私钥与密码不进入 Git。

历史补丁、快照与旧检查已归档到 `tools/legacy/`，不再是当前源码或构建输入。

## 1.0 存档

第一次进入普通存档免费获得 Bf-109 B-1、F3F-2、I-15bis、I-15；流星、B-29、MiG-15、F-86 暂不开放研发和购买。各系按本系前一个 BR 阶段入库的飞机独立开放下一阶段，不再使用跨国家的统一前置。C-1 的研发费用为 1600 RP / 4500 GP，与当前 Rank II MiG-3 费用相同。

`data/all-aircraft-1.0.json` 是单独的全解锁测试存档，包含全部 12 架飞机。主界面 → 设置 → 导入存档，选择此 JSON 即可使用；导入会替换当前进度，设置页会标识全解锁测试存档。普通安装不会自动全解锁。只有 1.0 格式可导入，存储失败会回滚；Android 使用系统文件选择器，不需要申请全盘存储权限。

C-1 模型机头沿 -Z、Y 向上，按机长 8.55 m 统一缩放，保留默认涂装。追尾相机沿用 B-1 的机尾后 8 m、机体中心上方 3.8 m，并采用相同的窄屏适配。长度和相机数据不加入图鉴。

所有机枪、航炮及 B-29 炮塔都有白色烟雾轨迹，留在世界坐标中，在 0.6 秒内扩散、淡出；所有轨迹共用一个固定容量的 GPU 绘制批次，重开和返回菜单会清理。炮塔沿用原命中与伤害计算，只补充弹道烟雾表现。
